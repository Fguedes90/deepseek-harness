# Agent Note: Drop unmounted provider packages

Status: implemented

## Problem

Three fully-built provider packages have no production mount anywhere in the repository: `packages/web/web-search-perplexity` (a Perplexity-backed `WebSearchProvider`), `packages/storage/storage-sqlite` (the `sqlite` backend of the non-session storage seam), and `packages/session/session-title-all-prompts-llm` (the `all-prompts` cadence provider of the log-backed title seam). Each registers into a documented capability seam (`ctx.web`, `ctx.storage`, `ctx.sessionTitle`), but no assembly mounts it.

A seam exists to serve product behavior, not to hold every provider written for it. Three provider packages carrying tests, READMEs, invariant companions, workspace entries, and generated-catalog rows for surfaces no composition uses is dead weight: they compile, pass their own tests, and produce 100% coverage while contributing nothing to a running product.

## Decision

Delete the three packages and every reference to them, keeping the Service Definition and registration API of each seam intact.

| Package | Seam | Registered as | Capability given up | Rebuild condition |
| --- | --- | --- | --- | --- |
| `web-search-perplexity` | [`ctx.web`](../../../../packages/web/web) | search provider `perplexity` | Perplexity-backed web search (OpenAI-compatible `/chat/completions`), mapping its generated answer plus `search_results[]`/`citations[]` into `WebSearchResult` | A composition wants Perplexity search and mounts it with a `PERPLEXITY_API_KEY`; rebuild against the [web capability seam note](../architecture/2026-06-24-web-capability-seam.md) |
| `storage-sqlite` | [`ctx.storage`](../../../../packages/storage/storage) | backend `sqlite` | SQLite `kv` facet over one `node:sqlite` database file, per-key precise durable updates and multi-process WAL writes | A domain routes to a high-frequency point-update table at scale, or multi-process write protection is needed; the [domain storage proposal](../../proposed/architecture/2026-07-24-domain-kv-storage-and-workspace.md) keeps the sqlite backend design unbuilt for exactly this condition |
| `session-title-all-prompts-llm` | [`ctx.sessionTitle`](../../../../packages/session/session-title) | cadence `all-prompts` | Retitling a session after every eligible human prompt, passing all eligible messages (including seeded history) through each revision | A deployment wants continuous model retitling after every prompt rather than once per fresh session; the `all-prompts` value remains a valid `SessionTitleAutomaticMode` on the seam |

### Evidence: no production consumer

The zero-consumer claim was verified before deletion with a repository-wide `rg` for each package name, excluding only the generated doc catalogs (`docs/config-catalog.md`, `docs/module-graph.md`, `docs/capability-seams.md`) and the frozen archive. Each name appeared only in its own directory (src, tests, README, package.json, `lib/` build output), `knip.json`, `tsconfig.host.json`, `pnpm-lock.yaml`, the seam tables in `scripts/gen-doc-graphs.ts`, workspace group READMEs, `docs/subsystems/`, and Agent Notes — never in a composition.

| Mount surface checked | Result |
| --- | --- |
| `packages/bundle/*/cordis.patch.yml` | none names the three packages |
| `apps/cli/config/agent-presets/*/agent.cordis.yml` | none names them |
| `examples/**/*.cordis.yml` | none names them |
| `apps/*/package.json` | no dependency on them |
| any other package's `src` or `package.json` | no import, dependency, or peer reference |
| `packages/web/tool-web/package.json`, `packages/bundle/*/package.json`, `examples/package.json` | no dependency entry |

The only references cut, beyond each package's own directory, were: the workspace group README rows and prose (`packages/web/README.md`, `packages/storage/README.md`, `packages/session/README.md`, `packages/web/web/README.md`), the seam `implementations` arrays in `scripts/gen-doc-graphs.ts`, the `knip.json` workspace entry for `web-search-perplexity`, the `tsconfig.host.json` project references, the inline names in `docs/subsystems/web.md` and `docs/subsystems/storage.md`, and current-state prose in Agent Notes that described the packages as shipped. The generated catalogs (regenerated by the main agent) and `pnpm-lock.yaml` (needs a `pnpm install` refresh) remain.

### Deleting a provider does not collapse the seam

Each deleted package was one *implementation* of a documented two-implementation capability seam. The seam itself — the Service Definition, its provider/backend registration API, and the selection or folding semantics — survives in the hub packages:

- **Web**: `packages/web/web` still owns `ctx.web`, `registerSearchProvider`/`registerFetchProvider`, selection, and `WebError`; the shipped search providers are Exa and DeepSeek plus the `http` fetch provider. Deleting the Perplexity provider does not change the normalized `WebSearchRequest`/`WebSearchResult` vocabulary or the "single auto-select, explicit id otherwise" selection rule.
- **Storage**: `packages/storage/storage` still owns the `ctx.storage` backend registry and the `kv` facet contract; `storage-json` remains the shipped backend. Deleting the sqlite backend leaves the seam with one implementation but keeps the registration API and the domain layer (`storage-domain`) untouched. The storage seam is explicitly designed for multiple backends to stay mounted side by side, and the sqlite backend's design record survives unbuilt in the [domain storage proposal](../../proposed/architecture/2026-07-24-domain-kv-storage-and-workspace.md).
- **Session titles**: `packages/session/session-title` still owns `ctx.sessionTitle`, the deterministic fallback, the `first-prompt` provider, and the `SessionTitleAutomaticMode` union that keeps `all-prompts` as a valid registered cadence.

The repository protects seams — the capability and its registration API — not every provider ever written against them. A provider package is only worth keeping while a composition mounts it; the seam contract is the durable surface.

## Consequences

Bought: the three packages' LOC, tests, READMEs, invariant companions, workspace entries, and generated-catalog rows for unmounted surfaces are gone; a reader is no longer directed to provider packages no product composes. The storage and session group READMEs that described a two-backend / two-provider choice now describe the single shipped implementation without losing the seam contract.

Cost: Perplexity web search, the sqlite `kv` backend, and all-prompts retitling are not available in any shipped composition; each returns only when a product condition (above) mounts it, at which point it is rebuilt against the surviving seam. The generated catalogs (`docs/config-catalog.md`, `docs/module-graph.md`, `docs/capability-seams.md`) must be regenerated, and `pnpm-lock.yaml` needs a `pnpm install` refresh.

## Alternatives considered

- **Keep the packages for "future" providers.** Rejected: each duplicates an existing capability (Exa/DeepSeek already search, json already stores, first-prompt already titles), so keeping them is speculative surface, not insurance. The seam contract — the durable thing — survives, and each backend's design rationale is preserved in its owning note, so nothing is lost to a future rebuild that the packages themselves carried.
- **Keep one and drop others.** Rejected: the zero-consumer evidence is uniform across all three — none is mounted anywhere — so there is no basis to spare one. Each is deleted under the same rule.
- **Delete the seam instead of the provider.** Rejected for the web and storage cases because the Service Definition and its registration API are load-bearing and documented; the storage seam is explicitly designed for multiple backends, and the domain layer consumes it. For session titles the seam owns the fallback and the `first-prompt` provider that compositions actually mount. The seam is the product contract; a provider is a choice under it.
